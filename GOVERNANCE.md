# Governance

## Project model

The project uses a maintainer-led, consensus-seeking model. Maintainers are accountable for repository security, releases, community health, and technical direction.

## Decision making

Routine changes are decided through pull-request review. Material changes should begin with an issue and document alternatives, security impact, compatibility, and migration concerns.

Maintainers seek consensus. When consensus is not practical, the lead maintainer makes the final decision and records the rationale in the issue or pull request.

## Maintainer responsibilities

Maintainers are expected to:

- Enforce the code of conduct and security policy.
- Protect credentials and release environments.
- Require review and passing checks before merge.
- Keep dependencies and pinned GitHub Actions current.
- Triage security reports privately.
- Publish release notes, checksums, SBOMs, and attestations.
- Disclose conflicts of interest relevant to a decision.

## Becoming a maintainer

A contributor may be invited after sustained, high-quality participation that demonstrates technical judgment, respectful collaboration, and security awareness. Existing maintainers decide by consensus.

## Inactivity and removal

A maintainer may step down at any time. Access may be removed for extended inactivity, compromised credentials, repeated policy violations, or conduct that puts users or the project at risk.

## Changes to governance

Governance changes require a pull request, public rationale, and approval from the lead maintainer.
